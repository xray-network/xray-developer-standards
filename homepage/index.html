01 — XRAY Updates Standard
xray/updates · 1.0.0

XRAY Updates Standard

Make each implementation explainable from plan to approval.

XRAY Updates is a Markdown-only control system made entirely of .md files stored in the repository. Installation simply creates those tracking files—there is no service, database, runtime dependency, or product-source change. The files connect bounded instructions, declared inputs, completed changes, validation results, and final human decisions.

How the workflow operates

One prompt can create a single bounded implementation for one change, or several separately numbered, bounded implementations when the request contains multiple distinct changes. Each follows PLANNED → REVIEW → ACCEPTED / REJECTED; planning does not change product source, and final decisions remain human.

  1. 01
    PLANNED — Define the implementation

    Give the AI agent one focused objective, the relevant repository context, constraints, expected outcome, and validation needs. The agent creates a complete implementation instruction and its matching PLANNED row in .xray/updates/XRAY-UPDATES-STATUS.md without changing product source.

  2. 02
    REVIEW — Implement and validate

    Tell the AI agent: “Implement this change.” The installed .xray/updates/XRAY-UPDATES.md defines the required workflow. After the result exists and validation is honestly recorded, confirm the ledger row moves to REVIEW in .xray/updates/XRAY-UPDATES-STATUS.md. While it is in review, you can continue working with the implementation: request changes, audit the source and evidence, rerun validation, and correct the result before making the final decision.

  3. 03
    ACCEPTED / REJECTED — Record the human decision

    A reviewer compares the result with the instruction and evidence, then records a reasoned ACCEPTED or REJECTED decision. Confirm the final state and its decision proof in .xray/updates/XRAY-UPDATES-STATUS.md, the sole lifecycle ledger. Terminal records stay immutable.

02 — XRAY Design Standard
xray/design · 1.0.0

XRAY Design Standard

Turn a visual language into an implementation contract.

XRAY Design combines machine-readable tokens with explicit rules for layout, components, interaction, accessibility, responsive behavior, light and dark themes, and product voice.

How to apply the system

  1. 01
    Prompt the required interface changes

    State the objective, affected screens and components, expected behavior, breakpoints, constraints, and completion criteria. Require the agent to read XRAY Design and inspect the existing interface first.

  2. 02
    Implement against the design contract

    Apply semantic tokens, component and layout rules, interaction states, accessibility, and product voice. Preserve behavior outside scope and record necessary deviations.

  3. 03
    Validate conformance before completion

    Check both themes, keyboard and focus behavior, responsive layouts, content states, and the no-shadow and no-gradient rules. Compare representative screens with the visual reference.

03 — Operating idea
01 / READPin the complete standard

Keep the versioned Markdown in the repository so a mutable website, missing browser context, or future release cannot silently change the rules governing current work.

02 / BUILDShare explicit context

Point repository instructions to the pinned document. Humans and coding agents can then make decisions from the same constraints, vocabulary, and completion criteria.

03 / VERIFYCheck the whole outcome

Review implementation evidence and visible behavior, not just changed files. Confirm the work still satisfies repository instructions, standard rules, accessibility, and human intent.
